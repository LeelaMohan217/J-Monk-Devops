# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — start the Vite dev server with HMR
- `npm run build` — production build (outputs to `dist/`)
- `npm run preview` — serve the production build locally
- `npm run lint` — run ESLint over the project

There is no test suite configured in this project (no test runner/framework in `package.json`).

## Git conventions

- Commit messages are a single plain subject line describing the change (e.g. `Highlight landing headings in red Playfair italic`). No body, and no trailers — in particular, do **not** append `Co-Authored-By:` or any other Claude/Anthropic attribution line.

## Architecture

This project hosts multiple marketing/company websites under one JMonkDevops umbrella, built with React 18 + Vite, React Router, Tailwind CSS, and Framer Motion, all sharing a single build/deploy. There is no backend — everything is static/client-side.

- **Multi-site layout**: each brand lives in its own folder under `src/sites/<sitename>/`, all three following the same `pages/`, `config.jsx`, `headingStyles.js` shape, with `assets/` where the brand has imagery (DigiConnect and EduConnect do; SkillConnect is deliberately type-only). `digiconnect` is the original site, rebranded. All three are now built out as multi-page sites. Cross-site reusable code lives in `src/shared/`.
- **Site config pattern**: each site's `config.jsx` exports a config object (`digiConnectConfig`, `skillConnectConfig`, `eduConnectConfig`) holding that site's branding and shared-component inputs — `siteName`, `homeHref`, `navItems`, nav CTA, `footer` (description/social links/quick links/address/phone/email), and `contactCta` (the CTA-banner heading/subtext/button). Each `<Sitename>App.jsx` imports its config and spreads it into the shared components as props. Every brand now has its own contact page, so all nav CTA and contact-banner hrefs point within the brand's own base path. `contactCta` also takes `maxWidthClass` and a `variant` (`"panel"` for DigiConnect and SkillConnect, the default banner for EduConnect), and its heading prop is `headingLead`/`headingAccent`, not `heading`. Adding a new site means creating an equivalent config object and wiring its own routes/pages — the shared components don't hardcode any brand's content.
- **Two-tier navigation**: there are two distinct navbars stacked on every brand page. `src/shared/components/GlobalNav.jsx` is the persistent, brand-agnostic top bar rendered once in `App.jsx` above all routes — it shows the JMonkDevops logo (always links to `/`) and flat links to each brand (`DigiConnect`/`SkillConnect`/`EduConnect`; unbuilt brands render as muted, non-clickable text) plus a placeholder search icon. `src/shared/components/Navbar.jsx` is the contextual sub-bar rendered by each brand's own app component (e.g. `DigiConnectApp`) — it shows that brand's `siteName` as a plain label (no logo/home-link of its own, since `GlobalNav` already owns that) plus that brand's own nav items and CTA button. Both bars share the same container padding (`px-8 lg:px-8 xl:px-20`, no `max-w` constraint) so their content aligns vertically.
- **Shared components** (`src/shared/components/`): `GlobalNav`, `Navbar`, `MobileNavMenu`, `MenuToggleIcon`, `GlobalFooter`, `ContactCmp` (CTA banner), `ContactForm`, `WordReveal`, and `CountUp` are brand-agnostic — they take branding/content as props rather than importing it, so any site can reuse them by passing its own config. `CountUp` animates a stat string ("100+", "98%") up to its final figure; the caller owns the in-view trigger and passes `start`, because a group of tiles has to count on the one trigger its reveal already runs on.
- **Shared animation**: `src/shared/variants.js` exports Framer Motion variant factories (`fadeIn(direction, delay)`, `riseIn(delay)`, `stagger`) reused across pages via `motion.*` components with `variants`/`initial`/`animate`/`whileInView`. The *choreography* those variants run on lives in `src/shared/motionConfig.js` and is shared by the landing page and the brand pages: `centerTrigger` (spread onto a motion component for the standard in-view trigger, which fires at the viewport's centre line via an IntersectionObserver `rootMargin` rather than at the bottom edge), `groupContainer` for a set of items sharing one trigger, `STEP` for the interval between them, and the `HERO_*` delays for a hero's mount-timed entrance. Two rules the comments in that file spell out: never pair `centerTrigger` with a `viewport.amount` threshold (amount is measured against the shortened observer root, so a tall group can never satisfy it and would never fire), and a group only shares one trigger if its items sit close enough together to still be on screen when their turn comes — a tall stack gets a trigger per item with no index delay instead (see `FAQSection`, and the `useIsDesktop` row-versus-stack split in `DashboardGridSection` and EduConnect's `ServicesSection`). `src/shared/components/WordReveal.jsx` is the hero heading treatment: each word lifts out of its own clipping mask, fed by `splitAccentHeading(lead, accent)` from `src/shared/splitAccentHeading.js` for the `headingLead`/`headingAccent` string pairs the sites' `data.js` files store.
- **Shared contact form logic**: `src/shared/hooks/useContactForm.js` is a hook wrapping EmailJS (`emailjs-com`) submission (form state, validation, send, success/error messaging) parametrized by `serviceId`/`templateId`/`publicKey`/`initialFields`, so each site's contact page supplies its own EmailJS credentials and field shape while reusing the same submit logic.
- **Routing**: `src/App.jsx` defines a `BrowserRouter` rendering `GlobalNav` once, then top-level `Routes`: `/` renders `src/pages/Landing.jsx` (the JMonkDevops umbrella page, composed from section components in `src/pages/home/` — hero, platforms, capabilities, etc.; `Landing` does not render its own header since `GlobalNav` already covers it), and `/digiconnect/*`, `/skillconnect/*`, `/educonnect/*` each render their site's `<Sitename>App.jsx`, lazy-loaded via `React.lazy`/`Suspense` for per-site code splitting. Each site owns nested `Routes`: DigiConnect has `""`, `about`, `services`, `careers`, `contact`; SkillConnect has `""`, `about`, `services`, `contact`; EduConnect has `""`, `about`, `services`, `blog`, `blog/:slug`, `contact`. Each app renders the shared `Navbar`/`Footer`/`ContactCmp` using its own config — note all hrefs in a site's config (nav items, footer quick links, contact CTA) are prefixed with that site's base path. A top-level `ScrollToTop` component (using `useLocation` + `useEffect`) scrolls to top on every route change, including nested ones.
- **Per-site pages & content**: every page across all three brands follows the same shape — a thin `pages/<Page>.jsx` that composes section components out of a `pages/<page>/` folder, with all of that page's copy in a sibling `data.js` so the sections stay purely presentational. DigiConnect has `Home`/`About`/`Services`/`Careers`/`Contact`, SkillConnect has `Home`/`About`/`Services`/`Contact`, and EduConnect adds `Blog`/`BlogPost` on top of the same four (its posts live in `src/sites/educonnect/blogPosts.js`). SkillConnect and EduConnect keep their contact pages as single files rather than a section folder, since each is just a header plus the shared `ContactForm`. Much of the copy is still marked `PLACEHOLDER` in the relevant `data.js` — EduConnect's hero stats, its 4.8 rating, and all five testimonial quotes/names are stand-ins, and the reviewer portraits are now attached to those stand-in names, so faces, names, and quotes have to be replaced together.
- **Heading type scale**: the size ramp for every page's opening `h1` comes from `src/shared/headingSizes.js`, not from per-component class strings. `HERO_HEADING_SIZE` (`display-xs` → `sm:display-sm` → `md:display-md` → `lg:display-lg`, i.e. 32/40/56/76px) is for full-width heroes; `PAGE_HEADING_SIZE` stops one step short at `md:display-md` and covers inner page headers plus any hero whose heading shares its row (EduConnect's two-column home hero). The `display-*` tokens are defined in `src/index.css`'s `@theme` and carry their own `line-height`/`letter-spacing` per step, so a component using these constants must not also set `leading-tight`/`tracking-tight`. Two rules matter: the base step never carries a breakpoint prefix (Tailwind's are min-width, so a ramp starting at `sm:` leaves phones on the inherited 16px), and per-brand heading *accent* still lives in each site's own `headingStyles.js` — size is shared, voice is not. Section `h2`s are the other heading family and do not use these constants: they run `text-3xl sm:text-4xl md:text-5xl font-semibold tracking-tight` with an explicit `leading-[1.1]`, which all 23 of them across the three brands and the landing page now share. Not `leading-tight` — that is 1.25, which at 48px opens a 12px trench between lines and reads as two statements rather than one sentence. So line height is reduced for both families, but by different means: the tokens carry it for `h1`s, a class carries it for `h2`s. The one deliberate exception is the landing hero's `leading-[1.05]`, which overrides its token because `WordReveal`'s per-word clipping masks need a single line-height across every breakpoint to keep their padding one em value.
- **Styling**: Tailwind CSS (config in `tailwind.config.js`, scans `index.html` and `src/**/*.{js,ts,jsx,tsx}`) is the primary styling mechanism — components use inline `className` utility strings almost exclusively. The accent color is red (`red-600`/`red-700`) across brands by design (one consistent JMonkDevops palette), currently hardcoded in the shared components' Tailwind classes rather than themeable.
- **Images**: each site's static assets live in its own `src/sites/<sitename>/assets/` folder and are imported directly into that site's components or `data.js`; the shared JMonkDevops logo used by `GlobalNav`, `Navbar`, and `MobileNavMenu` lives at `src/shared/assets/Logo.webp`. Photos are committed as a `.jpg` + `.webp` pair and served through a `<picture>` with the webp as the `<source>`. Keep them sized to what actually renders: the assets folders were carrying ~48MB of unreferenced originals (three 10-15MB JPEGs among them) until a cleanup pass removed everything no module imported. Nothing here is served from `public/` except the favicons.
