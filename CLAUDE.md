# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — start the Vite dev server with HMR
- `npm run build` — production build (outputs to `dist/`)
- `npm run preview` — serve the production build locally
- `npm run lint` — run ESLint over the project

There is no test suite configured in this project (no test runner/framework in `package.json`).

## Git conventions

- Commit messages are a single plain subject line describing the change (e.g. `Highlight landing headings in red Playfair italic`). No body, and no trailers — in particular, do **not** append `Co-Authored-By:` or any other Claude/Anthropic attribution line.

## Architecture

This project hosts multiple marketing/company websites under one JMonkDevOps umbrella, built with React 18 + Vite, React Router, Tailwind CSS, and Framer Motion, all sharing a single build/deploy. There is no backend — everything is static/client-side.

- **Multi-site layout**: each brand lives in its own folder under `src/sites/<sitename>/` — `digiconnect` (the original "J-Monk Devops" site, rebranded; full multi-page site with `pages/`, `assets/`, `constants/`, `config.jsx`), and `skillconnect`/`educonnect` (newer brands with a single basic `Home` page each, following the same `pages/`, `assets/`, `config.jsx` shape but not yet built out beyond that). Cross-site reusable code lives in `src/shared/`.
- **Site config pattern**: each site's `config.jsx` exports a config object (`digiConnectConfig`, `skillConnectConfig`, `eduConnectConfig`) holding that site's branding and shared-component inputs — `siteName`, `homeHref`, `navItems`, nav CTA, `footer` (description/social links/quick links/address/phone/email), and `contactCta` (the CTA-banner heading/subtext/button). Each `<Sitename>App.jsx` imports its config and spreads it into the shared components as props. SkillConnect and EduConnect currently reuse DigiConnect's contact page (`/digiconnect/contact`) for their nav CTA and contact-banner links since they don't have their own contact form yet. Adding a new site means creating an equivalent config object and wiring its own routes/pages — the shared components don't hardcode any brand's content.
- **Two-tier navigation**: there are two distinct navbars stacked on every brand page. `src/shared/components/GlobalNav.jsx` is the persistent, brand-agnostic top bar rendered once in `App.jsx` above all routes — it shows the JMonkDevOps logo (always links to `/`) and flat links to each brand (`DigiConnect`/`SkillConnect`/`EduConnect`; unbuilt brands render as muted, non-clickable text) plus a placeholder search icon. `src/shared/components/Navbar.jsx` is the contextual sub-bar rendered by each brand's own app component (e.g. `DigiConnectApp`) — it shows that brand's `siteName` as a plain label (no logo/home-link of its own, since `GlobalNav` already owns that) plus that brand's own nav items and CTA button. Both bars share the same container padding (`px-8 lg:px-8 xl:px-20`, no `max-w` constraint) so their content aligns vertically.
- **Shared components** (`src/shared/components/`): `GlobalNav`, `Navbar`, `Footer`, `ContactCmp` (CTA banner), and `ScrollToTopButton` (currently unused/commented out in `App.jsx`, renders via `createPortal` into `#portal-root` in `index.html`) are brand-agnostic — they take branding/content as props rather than importing it, so any site can reuse them by passing its own config.
- **Shared animation**: `src/shared/variants.js` exports Framer Motion variant factories (`fadeIn(direction, delay)`, `stagger`) reused across pages for scroll/entry animations via `motion.*` components with `variants`/`initial`/`animate`/`whileInView`.
- **Shared contact form logic**: `src/shared/hooks/useContactForm.js` is a hook wrapping EmailJS (`emailjs-com`) submission (form state, validation, send, success/error messaging) parametrized by `serviceId`/`templateId`/`publicKey`/`initialFields`, so each site's contact page supplies its own EmailJS credentials and field shape while reusing the same submit logic.
- **Routing**: `src/App.jsx` defines a `BrowserRouter` rendering `GlobalNav` once, then top-level `Routes`: `/` renders `src/pages/Landing.jsx` (the JMonkDevOps umbrella page, composed from section components in `src/pages/home/` — hero, platforms, capabilities, etc.; `Landing` does not render its own header since `GlobalNav` already covers it), and `/digiconnect/*`, `/skillconnect/*`, `/educonnect/*` each render their site's `<Sitename>App.jsx`, lazy-loaded via `React.lazy`/`Suspense` for per-site code splitting. `DigiConnectApp` owns nested `Routes` (relative paths `""`, `about`, `student`, `businessman`, `contact`); `SkillConnectApp`/`EduConnectApp` currently only have a `""` (Home) route. Each app renders the shared `Navbar`/`Footer`/`ContactCmp` using its own config — note all hrefs in a site's config (nav items, footer quick links, contact CTA) are prefixed with that site's base path. A top-level `ScrollToTop` component (using `useLocation` + `useEffect`) scrolls to top on every route change, including nested ones.
- **Per-site pages & content**: `src/sites/digiconnect/pages/` (`Home`, `About`, `Student`, `Businessman`, `Contact`) are large presentational components — note this content (including the Student/internship-focused page) predates the DigiConnect rebrand and hasn't yet been rewritten around DigiConnect's actual positioning (software development/cloud/DevOps services); treat it as a placeholder pending a content pass. `src/sites/digiconnect/constants/index.jsx` holds this site's page-content data arrays (service/offering descriptions, `studentPageData`/`offeringPageData`/etc.) — branding/nav/footer data was moved out of here into `config.jsx`. `src/sites/skillconnect/pages/Home.jsx` and `src/sites/educonnect/pages/Home.jsx` are single basic pages (hero, offerings/services grid, "why choose us" list) built from the brand content PDF — both are intentionally minimal pending a full multi-page build-out like DigiConnect's.
- **Styling**: Tailwind CSS (config in `tailwind.config.js`, scans `index.html` and `src/**/*.{js,ts,jsx,tsx}`) is the primary styling mechanism — components use inline `className` utility strings almost exclusively. The accent color is red (`red-600`/`red-700`) across brands by design (one consistent J-Monk Devops palette), currently hardcoded in the shared components' Tailwind classes rather than themeable.
- **Images**: each site's static assets live in its own `src/sites/<sitename>/assets/` folder and are imported directly into that site's components/constants/config; the shared JMonkDevOps logo mark used by `GlobalNav` and `Landing` lives at `src/shared/assets/Logo.png`. `react-lazy-load-image-component` (with the `blur` effect) is used for lazy-loaded images.
